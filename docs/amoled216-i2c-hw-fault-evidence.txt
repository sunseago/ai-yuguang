AI余光 · Waveshare ESP32-S3-Touch-AMOLED-2.16 · I2C 硬件故障证据
================================================================

板卡：Waveshare ESP32-S3-Touch-AMOLED-2.16（SKU 33969）
日期：2026-11-11

现象
----
屏幕（CO5300 / QSPI，GPIO 4/5/6/7/38/12/39）工作正常，能正常显示画面；
但 I2C 总线（GPIO15 = SDA，GPIO14 = SCL）上**所有**器件均无应答：

    AXP2101  电源管理   0x34
    CST9220  触摸       0x5A
    QMI8658  六轴 IMU   0x6B
    PCF85063 RTC        0x51
    ES8311   音频 codec 0x18

后果：触摸失效、陀螺仪（自动转屏）不可用、电池电压与充电状态读不到。

实测定位（每一步都有对照组）
----------------------------
1. 引脚定义核对 —— 与微雪官方文档 / 官方示例一致：
   SDA=GPIO15、SCL=GPIO14、TP_RST=GPIO40、TP_INT=GPIO11。
   另试 6 组候选引脚对（含 SDA/SCL 互换），全部 0 器件。排除接错脚。

2. 速度相关排除 —— 绕开 ESP32 的 I2C 外设，用 GPIO 位翻转扫描全地址
   （0x08~0x77），时钟降到 ~12kHz（弱上拉也能跑通），仍然 0 器件。
   排除"上拉太弱 / 速度快"。

3. 应用固件排除 —— 写了一个最小探针（只 Wire.begin + 扫地址，
   不初始化屏幕、不加载任何库），结果同样是 0 器件。

4. 总线是否被从机按住 —— 空闲时在"无内部上拉"和"有内部上拉"两种情况下
   都读到 SDA=1 / SCL=1，未被拉死。

5. 短路判定（关键）—— 推挽把 SDA 拉低，用 ADC 读 SCL 的实际电压：

       SDA 拉低 -> SCL 读到 204mV (raw 228)
       SCL 拉低 -> SDA 读到 208mV (raw 229)
       对照：GP17 拉低 -> GP18 读到 4095（无耦合，测量方法可信）

   两线之间存在 ~140Ω 的低阻通路。
   若只是"总线上有未上电器件、其 ESD 二极管把两线经共同 VDD 钳位"，
   被拉的那根应停在 0.6~1.4V（一个 PN 结压降）；实测仅 0.2V，故排除该可能。

6. 供电排除 —— 拔掉电池、仅 USB 供电、重新上电后依旧短接；
   30 秒内 600 次采样全部导通，从未出现瞬时恢复（不是接触不良的抖动）。

7. 原理图核对（schematic/ESP32-S3-Touch-AMOLED-2.16-Schematic.pdf）：
   · R21 / R22 = 2.2k 上拉至 VCC3V3（ESP32_SCL / ESP32_SDA），
     与 140Ω 反推一致，同时说明 VCC3V3 正常（否则上拉不存在）。
   · 触摸 I2C 经 J4（24pin 屏排线）走到屏体：pin18=TP_RESET、
     **pin19=TP_SDA、pin20=TP_SCL（相邻两脚）**、pin21=QSPI_SI2。
   · 板上没有 I2C 专用 ESD/TVS 器件（只有 USB 上的 TVS1 = LTVS16H5.0ET5G），
     排除"保护器件击穿"。

结论
----
SDA 与 SCL 之间存在约 140Ω 的硬件搭连。两线短接时 I2C 物理上无法完成任何
一次合法传输，因此全部从机同时"消失"，而走 QSPI 的屏幕不受影响。
断电无法恢复，固件无法绕过。

最大嫌疑：J4 屏排线座 / 排线本身（pin19 与 pin20 相邻）。
